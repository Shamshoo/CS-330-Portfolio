# CS-330 Computational Graphics and Visualization

This repository contains my final project for CS-330, a 3D recreation of a home office desk that I made in C++ and OpenGL. The ZIP folder contains the Visual Studio project, source code and EXE for the 3D scene, and the design decisions document explains my choices for it.

The scene is based on a photo of a home office desk. A tall table lamp, monitor on an arm, keyboard, small gold mushroom lamp, a game console and a candle are modeled from boxes, cylinders, spheres, a torus and a tapered cylinder. The scene also contains textures, three point lights with Phong lighting, and a camera you can fly around with the keyboard and mouse. W, A, S and D move it, Q and E move it up and down, the mouse looks around, the scroll wheel changes speed, O switches to orthographic view, P switches back to perspective, and Esc closes it.

## Reflection

This project helped me to break something complicated into simple pieces before I start writing any code. I looked at the photo and figured out which basic shape each object could be made from before I built the scene (torus, sphere, cylinder, tapered cylinder for the lamp). That made the coding easier because I knew in advance what each object required. I planned the scene in the proposal, built each object in turn and layered in the textures, lighting and the camera controls in the later milestones. I can apply that same approach to future work by planning the parts of a program in advance and building it in small layers rather than all at once.

When writing the program, I also had to learn to build and test in small steps. Each time I added an object or changed a value, I would run the program to check it before going on, and this made the problems much quicker to find. The idea of iteration was a big part of the project, as the positions, scales and light values almost never looked correct on the first attempt, so the values had to be tweaked over several iterations to match the photo. My approach also evolved with each of the milestones. At the beginning of the project I had placed all the drawing code into one function, but by the end I had separated each object into its own function, like RenderLamp() and RenderMonitor(), and had kept textures, materials and lights in their own setup functions, which made the code easier to read and add to.

Computational graphics also helped me to understand better what goes on behind the tools that I already use. I create games in Unreal Engine, and understanding the way transformations, textures, lights and cameras work at a lower level can help me to understand what the engine is doing and correct visual issues as they occur. Later classes will benefit from this foundation in matrix math and rendering, especially any course that involves visualization or game development. Game development, simulations and any software that has to show data visually are examples of the professional fields to which these skills apply, and habits that I learned here, such as planning before coding, testing in small steps and keeping code modular, will be applicable to almost any programming job.
